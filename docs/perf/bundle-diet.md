# 번들 줄이기 (BD-1) — 처음 받는 JS 의 구성과 지연으로 옮긴 것

예산(`src/lib/perf/bundle-budget.ts`)은 **그대로 두었다** — 되찾은 여유는 다음 기능의 몫이다. 크기는 모두 gzip KB, `npm run check:bundle` 의 잣대(경로마다 `rootMainFiles` ∪ 그 경로의 `entryJSFiles`, 파일마다 gzip 한 합)다.

## 재는 법 (다음 조각이 그대로 다시 쓴다)

```bash
npm run build
npx next experimental-analyze --output          # Next 16 이 싣고 오는 Turbopack 분석기 → .next/diagnostics/analyze (빌드 뒤에 — 빌드가 .next 를 비운다)
node scripts/bundle-breakdown.mjs '^/w/\[workspaceId\]/\[pageId\]/page$' --by=file --top=40   # 모듈별 KB
node scripts/bundle-breakdown.mjs '<경로>' --by=pkg                                            # 패키지 · 폴더별
node scripts/bundle-breakdown.mjs '<경로>' --cut="search-overlay.tsx;settings/mfa-panel"       # 그것을 지연시키면 몇 KB 가 빠지나
node scripts/bundle-breakdown.mjs '<경로>' --why=table-api.ts                                  # 왜 들어왔나(진입점까지의 사슬)
```

분석기 실행은 빌드와 청크 해시가 달라(서버 액션 id 등 — 파일마다 수십 바이트) 이름이 아니라 **크기가 가장 가까운 분석 청크**와 잇는다. 모듈별 KB 는 파일의 실제 gzip 을 분석 청크 안 원본 모듈의 `compressed_size` 비율로 나눈 **어림값**(±0.1)이고, 합은 실제와 같다. `--cut` 은 모듈 그래프(동기 의존)에서 후보를 끊고 진입점에서 다시 닿는 것만 남겨 뺀 값이라, 청크 경계에 덧붙는 몫(지연 청크 하나에 약 0.1~0.3KB)은 세지 않는다.

## 주의 — 예산이 세지 않는 몫

서버가 그리는 지연 부품(지금 설정 패널 · 행 페이지의 머리)은 그 청크를 `<link rel=preload>` 로 처음에 함께 받는다. 예산은 세지 않지만 그 화면의 실제 내려받기에는 든다 — 이번에 줄인 것은 **그 화면이 그리지 않는 것**(열지 않은 패널 · 보통 페이지의 행 부품)이라 실제로도 받지 않는다. 클릭으로 처음 그려지는 지연 부품은 자기 Suspense 경계가 없다(`loading` 을 주지 않는다) — 청크가 올 때까지 앞 화면을 그대로 두고 한 번에 나타난다(BX-2 와 같다). 그래서 첫 열림이 청크 받는 만큼 늦을 수 있어 열기 전에 미리 받는다(칩 · 패널).

서버가 그린 지연 부품은 HTML 이 먼저 보이고 하이드레이트는 그 청크가 들어온 뒤다 — e2e 가 HTML 만 보고 곧바로 만지면 React 가 듣지 못한다(전체 판에서 감사 로그 절이 거르기 없는 CSV 를 읽었다 → `waitHydrated` 를 기다리게 고쳤다). 지연으로 옮긴 패널을 만지는 절은 하이드레이트를 기다린다.
