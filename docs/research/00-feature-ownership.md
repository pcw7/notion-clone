# 00 — 기능 소유권 정리 (Feature Ownership & Canonical F-ID Registry)

> **작성 모드**: SYNTHESIS (기능 소유권 정리)
> **입력**: `docs/research/01~17-*.md` 17개 도메인 문서 전수 + `_critique/coverage-critique.md` C-16
> **목적**: 17개 문서가 각자 매긴 F-ID·난이도·우선순위를 하나의 로드맵으로 합칠 수 있게 만든다. 이 문서는 **기능을 새로 명세하지 않는다.** 어느 F-ID가 그 기능의 *정본(canonical)* 인지 선언하고, 난이도·우선순위를 하나로 확정하고, MVP 경계를 긋는다.
> **상태**: 이 문서가 난이도·우선순위에 대해 도메인 문서와 충돌할 경우 **이 문서가 우선한다.** 도메인 문서는 동작 명세의 출처로만 계속 유효하다.

---

## 0. 판정 규칙 (이 문서가 사용한 결정 알고리즘)

### R1 — 정본 소유권
1. **소유 도메인 우선**: 그 기능의 스키마와 코드 경로가 실제로 살고 있는 서브시스템의 문서가 소유한다. (예: 잠금 플래그는 쓰기 게이트이므로 권한 도메인, 차트는 view_type enum 위에 서므로 뷰 도메인)
2. **동률이면 서술 깊이**: 소유 도메인 후보가 둘 이상이거나 애매하면, 동작·엣지케이스를 더 깊게 쓴 쪽이 소유한다.
3. **정본이 더 얇은 경우**: R1-1로 정한 정본이 포인터 문서보다 서술이 얇으면 `정본 보강 필요` 로 표시했다. 이 경우 **포인터 문서의 본문을 정본으로 이관**하는 것이 후속 작업이다. (얇다는 이유로 소유권을 옮기면 같은 기능이 도메인 경계를 넘나들며 스키마가 다시 갈라진다.)

### R2 — 난이도 확정
- **가장 높은 값을 채택한다.** 과소평가가 로드맵을 망친다.
- 예외는 **기능이 실제로 두 개였던 경우에만** 허용한다. 예: `F-04-25`(L)는 "잠금 + 스키마 편집 권한 분리" 두 기능이 뭉친 값이므로, 분해 후 잠금 단독은 M으로 확정했다. 예외에는 근거를 표에 적었다.

### R3 — 우선순위 확정
- 판정 질문은 **"이게 없으면 제품이 성립하는가"** 하나다.
- 도메인 문서의 P0/P1은 **도메인 내부 상대 우선순위**인 경우가 많다(예: 15-external-sync의 P0는 전부 "(도메인 내)" 라고 명시돼 있다). 전역 우선순위로 승격하지 않았다.
- `P0` = 제품이 성립하지 않음 / `P1` = 경쟁력 없음 / `P2` = 없어도 됨.

### R4 — MVP 컷 (P0 ≠ MVP)
P0 102개를 그대로 만들면 6~8주에 끝나지 않는다. MVP 편입 기준은 다음 4개 중 하나에 해당하는 것뿐이다.

| 코드 | 질문 |
|---|---|
| (a) | 이게 없으면 **글을 쓸 수 없다** |
| (b) | 이게 없으면 **저장이 안 된다** |
| (c) | 이게 없으면 **남과 공유가 안 된다** |
| (d) | 이게 없으면 **로그인이 안 된다** |

**규칙 예외 1건 (명시적으로 선언한다)**: 최소 데이터베이스(F-03-01~F-04-15의 부분집합)는 위 4개 어디에도 해당하지 않지만 MVP에 넣었다. 근거 — 데이터베이스가 없는 산출물은 노션 클론이 아니라 마크다운 에디터이고, `page`가 곧 `database row`라는 불변식(F-03-01 / F-16-07)은 **나중에 끼워 넣을 수 없는 스키마 축**이다. 이 예외로 15개 항목이 MVP에 추가됐다.

## 2. 전체 F-ID 인벤토리

- `정본` = 이 F-ID가 해당 기능의 소유자.
- `→ F-XX-YY` = 이 F-ID는 포인터. 내용은 정본으로 이관하고, 원 위치에는 "정본: F-XX-YY 참조" 한 줄만 남긴다.
- 난이도·우선순위는 **각 도메인 문서가 스스로 매긴 원값**이다(파싱 결과). 서로 충돌하는 값의 **확정치는 3장**에 있다.

### 4.2 전수 재검증 결과

- 17개 문서에서 정규식 `F-[0-9]{2}-[0-9]{2}[a-z]?` 로 추출한 **참조 고유값 334개**와 `^### F-` 로 추출한 **정의 고유값 334개**가 **완전히 일치**한다. → **현재 dangling 참조 0건.**
- `F-11-11b`는 오타가 아니라 실제 정의된 ID다(`11-history-notifications.md:739` — Slack 채널 연동). 후행 알파벳을 쓰는 유일한 ID이므로 **번호 체계 규칙 위반**으로 표시하고, 통합 로드맵에서는 `F-11-19`로 리넘버링할 것을 권고한다 `[결정 필요]`.

### 4.3 dangling은 아니지만 정정이 필요한 참조
